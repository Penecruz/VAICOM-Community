LOG Tab

Overview: Primary operational feed for the mission briefing loaded dynamically at runtime. You can review the mission briefing at any time here without pausing the mission in single player.

Figure LOG-1. LOG tab overview image.

What You Should Use It For

  • Briefing confirmation: Understand the mission goals and get background information on the mission scenario.
  • Mission design awareness: Understand what you are trying to achieve in the loaded mission and gather relevant context.
  • Session tasks and instructions: generally mission designs also place relevant tasks and instructions here.

How Data Is Produced

  • Entries are assembled from the mission designers briefing notes.
  • Changing missions will fetch the latest briefing notes.

Controls

  • No tab-specific picker controls currently. Uses global controls only.

FLT PLN Tab

Overview: Flight plan viewer for Mission, DTC and RouteTool sourced files.

Contains: Structured table views of selected file content, mission timing, route data, page views (Time/NAVLOG/COM/CMDS/MAP), and map interaction readouts.

Purpose: This tab is intended as the mission planning and in-flight quick-reference board for timing, communications, commands, and route/map awareness.

Workflow

  1. Load the mission route package
    • Open Files (☰) and choose the active FLT PLN source (DTC or RouteTool).
    • Confirm the header updates with the selected package and route context.
    • If the expected file is missing, recheck export location and refresh file list workflow.
  2. Validate session and mission context
    • Open Session (ℹ) and verify aircraft, theatre, mission title, and current mission state.
    • Confirm route package aligns with the current sortie (avoid stale file from prior mission).
    • Close Session and return to FLT PLN for execution setup.
  3. Build your timing plan (TIME page)
    • Set/verify TOT as mission anchor timing.
    • Use mission-time readout to determine ahead/behind status against route progression.
    • Apply recommended speed schedule adjustments where needed to recover timing drift.
    • Mark ATA checkpoints as you progress through the mission.
  4. Cross-check route geometry and nav sequence (NAVLOG page)
    • Validate waypoint order, leg continuity, and key route values before push.
    • Use table/cell controls to inspect and adjust supported parameters.
    • Use NAVLOG as primary reference during enroute checks and reattacks.
  5. Configure support systems (COM / STORES / CMDS pages)
    • COM: Confirm frequencies/channels match current tasking and expected comm plan.
    • STORES: Validate payload, station assignment, and any mission-critical store constraints.
    • CMDS: Confirm loaded countermeasure programs and expected timing/sequences from DTC data.
  6. Maintain tactical picture (MAP page)
    • Toggle BG ON/OFF based on readability and mission need.
    • Use zoom/pan to inspect route legs, target area geometry, and divert options.
    • Use selection readouts for asset context and BRA/B-E style awareness where available.
    • Keep D-LINK ON when coalition datalink overlays are required.
  7. Execute in-mission update loop
    • Cycle pages as needed: TIME (timing), NAVLOG (route), COM (radios), CMDS/STORES (systems), MAP (SA).
    • Re-check timing after major events (takeoff, push, IP, target actions, egress, divert).
    • Use debug views only when troubleshooting data mismatches (raw JSON / server messages).
  8. Postflight capture and review
    • Use postflight controls/pages to record mission completion state and timing results.
    • Capture deviations between planned and actual timeline for follow-up tuning.
    • Retain the route package for debrief reference or refinement in next sortie.

Page Selection Modes

PAGE SELECTION

Figure 1. FLT PLN Page Selection and Postflight.
  • Mission-time and timing-centric readout panel. Can be clicked to mark current time and update mission clock context.
  • TOT can be edited to provide updated timing information and recommended speed schedule.
  • Used to mark ATAs at route checkpoints against mission clock context.
  • Supports quick verification of ahead and behind timings at route checkpoints.
  • Buttons for page navigation, DTC Route selection and postflight actions. See below for related information and usage.

NAVLOG

Figure 2. FLT PLN NAVLOG and waypoint management.
  • Primary navigation log view for route legs and waypoint sequencing.
  • Focuses on route progression, leg continuity, and planning data readability.
  • In-cell pop-up controls allow adjustment of supported waypoint parameters.
  • Clicking editable cells opens embedded pop-up editors (in-place) for quick value changes without leaving NAVLOG context.
  • Clicking certain cell headers changes data units where applicable.
  • Useful for cockpit cross-check against aircraft systems and required TOT, ATA and ETAs.

COM

  • Communications reference page for channels/frequencies/related comm data when present in the mission or loaded via a DTC.
  • Intended for rapid radio setup and in-flight comms validation.
  • Pairs well with ATC/AWACS/JTAC workflow tabs for live operations.

STORES

  • Stores reference page for munitions, fuel, and other external stores when loaded on the jet.
  • Updated dynamically and allows rapidin-flight validation.
  • Ideal for confirming stores station position, hung ordnance, and other critical information.

CMDS

  • DTC generated countermeasures program information.
  • Includes details on deployment sequences and timing.
  • This is data passed via DTC, does not reflect changes made by the pilot using the cockpit controls.

Data Sources and Notes

  • DTC files: Loaded from Saved Games DTC export paths when available.
  • RouteTool files: Parsed from RouteTool preset output where supported.
  • Embedded edit controls: Cell-activated pop-up editors are contextual and only appear on supported fields/pages.
  • Fallback behavior: If structured rendering is unavailable, a plain formatted data view is shown.
  • Debug support: Use global debug toggles (raw JSON/server messages) for troubleshooting content flow.

ATC Tab

Overview: Air Traffic Control and weather-reference tab for current airfield-focused communications.

Contains: ATC-related phrase references, active weather text, and selected-airfield METAR context when available.

Figure ATC-1. ATC tab overview (placeholder image).

What Is Displayed

  • ATC references: Phrase and context lines relevant to tower/approach interactions.
  • METAR/weather blocks: Parsed weather strings where export/runtime provides them.
  • Airfield context: Closest/selected field context influences which weather block is emphasized.

How It Is Calculated / Selected

  • Weather sections come from runtime weather/METAR data when present.
  • When multiple reports are available, user selection and click context determine the focused METAR line.
  • Pressure-unit toggles apply to displayed weather outputs, not mission physics.

AWACS Tab

Overview: AWACS command/reference and tactical air picture summary.

Contains: Available AWACS/EWR contributors, detected opposition contacts, grouped aircraft tracks, and contact-specific readouts.

Figure AWACS-1. AWACS tab overview (placeholder image).

What Is Displayed

  • Contributors: Friendly AWACS/EWR sources currently reporting.
  • Aircraft contacts: Air tracks may be grouped by proximity/formation behavior.
  • Emitter context: Opposing EWR/emitter references when available in source data.

BRA / Contact Readouts

  • BRA/Bulls style output: Bearing/range/aspect-style lines are derived from ownship and contact positions where available.
  • Bearing: Derived from ownship-to-contact geometry and displayed in tactical heading format.
  • Range: Derived from horizontal distance and displayed in mission-appropriate units.
  • Altitude/aspect: Included when source contact metadata contains sufficient values.

Data Quality Notes

  • Contact grouping and labels depend on available coalition runtime sensors and exported data cadence.
  • Displayed tactical values are situational aids and may differ from onboard radar/FCR behavior.

Controls

  • No dedicated tab-specific controls; uses global settings/help controls.

JTAC Tab

Overview: JTAC-focused communications, tasking context, and support cue reference panel.

Contains: JTAC call snippets, target/task references, and command-keyword guidance for attack flow support.

Figure JTAC-1. JTAC tab overview (placeholder image).

What Is Displayed

  • JTAC log stream: Nine-line and follow-on JTAC calls as received in-session.
  • Keyword references: JTAC command flow prompts and expected response cues.
  • EFB SA Map markup context: The JTAC tab text is the source context used to interpret map target overlays.

How To Use It

  • Use this tab to confirm the latest nine-line details before attacking.
  • Cross-reference the JTAC text with EFB SA Map symbols for rapid talk-on and run-in planning.
  • Use FLT PLN NAVLOG (IP/route) with JTAC attack-sector markup to build ingress alignment and attack geometry awareness.

EFB SA Map JTAC Markup (What Each Element Means)

  • Active JTAC TGT: Current assigned target from the most recent valid nine-line burst.
  • Friendly marker/line: Friendly reference from line 8 when available. A dotted line extensing from the TGT to the location of the friendly troops in contact.
  • Egress cue: Egress direction marker/line from line 9 when available. A red arrow that shows the required egress heading extending from the TGT 5 NM.
  • Attack sector: Reciprocal attack-heading sector from remarks/final heading constraints. A green arc sector that defines the direction to attack from, graduated in 5 NM sections.
  • Sector range bands: 1-5nm (primary), 5-10nm (lighter), 10-15nm (lightest) for longer fast-jet run-in planning.

JTAC Popup Content

  • Click a JTAC TGT symbol to open a condensed nine-line popup.
  • Popup format is line-based: 1-2-3 N/A, then lines 4 through 9, then RMK if present.
  • Each TGT popup keeps its resolved nine-line content for that target instance (active or history) to preserve tactical context if multiple targets and 9-Lines are received from the JTAC.

History Targets (TGT-1, TGT-2, ...)

  • When a new valid nine-line target is received, the prior active target is moved to history.
  • History targets are drawn as black labeled markers (TGT-1, TGT-2, ...).
  • History is capped to recent entries (up to 10) so pilots can retain prior target awareness without cluttering indefinitely.

Layer Toggle (On/Off)

  • In the EFB tab, open Layers while SA Map is active and use the JTAC layer button to show/hide all JTAC map markup.
  • Disabling the JTAC layer hides active/history JTAC symbols and support geometry without changing logged JTAC text.

Controls

  • No dedicated tab controls currently beyond global overlays.

EFB Tab

Overview: Electronic Flight Bag workspace for both chart viewing and SA Map moving-map operations using the same rail-control workflow.

Contains: Chart mode, SA Map mode, auto/manual airport workflows, pinned chart favorites, map/viewport controls, layer toggles, ownship follow/track-up controls, and asset/airfield bugging support.

Figure EFB-1. EFB overview (placeholder image).

Mode and Left Rail Controls

  • SA Map toggle: Switches the EFB viewport between chart mode and SA Map mode.
  • Auto (A): Resolves/selects airport from current mission context, then opens the chart list for that airport.
  • Airport (🗼): Opens airport list drawer first; selecting an airport opens its chart list.
  • Pinned (📌): Opens pinned drawer (favorites) showing only charts explicitly pinned from chart rows.
  • Search: Opens the stylus-oriented chart search overlay with radial character input and center token display.
  • Layers: Opens the SA Map layers drawer when SA Map mode is active.

Drawer Lists and Pinning

  • Chart list rows: Each chart row has a line pin icon. Toggle to pin/unpin that chart.
  • Pinned drawer behavior: Shows pinned charts from any airport as a global favorites list.
  • Pinned row format: Rows display AIRPORT · CHART NAME for clarity across multiple fields.
  • Unpin paths: You can unpin from either the airport chart list or from the pinned drawer itself.
  • Selecting pinned charts: Choosing a pinned row switches to that chart's airport and loads the selected chart.

Chart Search Tool

  • Radial search overlay: Designed for stylus/touch entry with wheel-based character selection.
  • Token display: The center token shows the current ICAO/search text being built.
  • Back: Removes the last entered character.
  • Clear: Resets the token and search candidate list.
  • Candidate selection: Choosing a result sets the airport/chart directly for quick access.

Chart View Controls

  • Zoom Out (−): Decreases chart zoom.
  • Recenter (⟳): Resets zoom and pan to default centered view.
  • Zoom In (+): Increases chart zoom.
  • Pan/drag: Click-drag in chart viewport to move the chart image.

SA Map Controls

  • Center Ownship: Recenters the map on ownship immediately.
  • Follow Ownship: Keeps map camera centered/anchored on ownship until explicitly turned OFF.
  • Track-Up: Rotates map to ownship heading until explicitly turned OFF.
  • Anchor: Toggles follow anchor position between center and lower-third framing.
  • Map zoom controls: The same right-rail zoom controls apply in SA Map mode.

SA Map Layers Drawer

  • D-Link assets: Show/hide friendly tactical assets while keeping ownship available.
  • Airports: Show/hide airfield symbols and labels.
  • Navlog route: Show/hide active route line and waypoint set.
  • DTC overlays: Show/hide DTC map overlays (threats, GEO lines, points, etc.).

SA Map Interaction Use Cases

  • Bug an asset/airfield: Tap/click symbols to select/deselect and show related detail context.
  • Manual inspect while following: Drag/zoom/rotate temporarily suppresses follow recentering, then follow resumes automatically.
  • Troubleshoot ownship source: Use the global GPS icon to compare fast ownship updates vs legacy server-position fallback.

Draw and Annotation Functions

  • NOTES draw mode (✎): Annotation draw tools remain on the NOTES tab only.
  • EFB behavior: EFB/SA Map currently focuses on chart and map interaction, not freehand annotation layers.

Night Mode and Chart Sources

  • Local folder charts: Night mode darkens chart brightness/contrast without hue swapping, so blue water and brown/orange terrain remain correct.
  • Navigraph charts: Dedicated provider-rendered night chart styling is expected when Navigraph chart mode is enabled.
